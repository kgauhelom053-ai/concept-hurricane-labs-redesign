What I’d fix for mobile and search

A short list of real issues I found on the live site, each with the evidence and the fix. The site is already fast and stable, so most of the wins are in metadata, structure and accessibility, which can be fixed inside Framer without a rebuild.

Issues, highest impact first

HighSEO

1. Every core page has the same title: “Hurricane Labs”

Evidence
All 25 non-blog URLs in sitemap.xml (homepage, /managed-soc, /managed-siem, /veeries-mdr, the five /industries/… pages, /about-us, /contact-us, /packages…) return <title>Hurricane Labs</title>. Blog posts already have unique titles.
Why it matters
Search results and browser tabs can’t tell the service pages apart, and none of them say what the page offers.
Fix
A unique title for each page in Framer’s page SEO settings, e.g. Managed SOC Services | 24/7 U.S.-Based SOC | Hurricane Labs (shown on the concept page).
HighSEO

2. One meta description reused on all 25 pages, and it’s too long

Evidence
Every core page uses the same 203-character description starting “Whether you need a fully outsourced solution…”. Google usually shows about 150–160 characters, so it gets cut off.
Fix
A page-specific description of about 140–160 characters that names the service and the next step (the concept page uses 152).
HighSEO

3. No structured data anywhere

Evidence
None of the 25 core pages contains application/ld+json, even though the footer already lists the address, phone and email.
Fix
Add Organization (name, address, phone, social profiles), Service on each service page, and BreadcrumbList, using Framer’s custom code in the page head. The concept page includes all of these plus FAQPage, as valid JSON-LD.
HighSEO · Mobile

4. Link previews, favicon and home-screen icon all use the wide wordmark

Evidence
Every page’s og:image and twitter:image is the same 1764×639 logo PNG. The same file is the light-mode favicon and the apple-touch-icon.
Why it matters
Shared links on LinkedIn or Slack get the same cropped logo for every page. A wide wordmark is unreadable at favicon size or as a phone home-screen icon.
Fix
A 1200×630 share image per key page, plus a square icon mark (180×180) for the favicon and touch icon.
MediumSEO · Accessibility

5. Heading structure is broken in several places

Evidence
The homepage has two H1s (the hero and the “Not sure where to start?” quiz), and so does /packages. /contact-us has no H1. On the homepage the testimonial is an H5 straight after an H2, which fails Lighthouse’s heading-order check. “Logo-less Security. By design.” is an H4 on desktop and an H2 on mobile.
Fix
One H1 per page, with H2 for sections and H3 for items inside them. Testimonials go in <blockquote>, not headings.
MediumSEO · Accessibility

6. “We’re fully U.S.-based” reads as “We’re fully” and “-based”

Evidence
In “Why teams choose us”, “U.S.” is a 94×72 image with alt="" placed between two separate H3 elements, so crawlers and screen readers get “We’re fully” and “-based”. This is one of your main selling points.
Fix
Make it one heading with “U.S.” as real text, and keep any flag graphic as decoration.
MediumSEO · Accessibility

7. Every homepage image has empty alt text

Evidence
All 55 <img> elements in the homepage HTML have alt="", including large content images such as a 2000×1600 PNG. Lighthouse passes this because the attribute exists, but no image is actually described.
Fix
Short descriptive alt text on meaningful images, and keep alt="" only for decorative ones.
MediumSEO · Accessibility

8. The headline stats aren’t readable as numbers

Evidence
The animated counters under the hero are built from digit strips. In the HTML, the first stat reads 0 1 2 3 4 5 6 7 8 0 1 2 3 4 5 % of alerts handled by our team instead of the figure shown on screen.
Fix
Put the final value in the markup as text (or as a visually hidden label) and keep the animation decorative with aria-hidden. The concept page shows the outcomes as plain text.
MediumMobile · Accessibility

9. Tiny, unlabelled carousel controls

Evidence
The five carousel dot buttons are 8×8 px and have no accessible name. The “Scroll to page” arrows are 20×30 px. Lighthouse mobile flags both target size and button names.
Fix
Hit areas of at least 24×24 px (44×44 is better on phones) and labels such as aria-label="Go to slide 2".
MediumAccessibility

10. Grey text below WCAG contrast, and unnamed social links

Evidence
Quiz answer and intro text uses #737C88 on white, a 4.23:1 contrast ratio (AA needs 4.5:1 for body text). Lighthouse also flags the “Logo-less Security” paragraph and the footer contact text. The footer LinkedIn and X icon links have no accessible name.
Fix
Darken the grey (for example #5F6873 is 5.65:1) and add aria-label to the icon links.
LowPerformance

11. Script weight on mobile

Evidence
My Lighthouse mobile lab run scored 92 for performance (FCP 2.5 s, LCP 2.5 s, CLS 0.003), which is good. It still reports 1.6 s of JavaScript execution and about 219 KiB of unused JavaScript. The biggest item is the HubSpot form embed (189 KiB, 109 KiB unused at load). The HTML document itself is 663 KB uncompressed, and the services cards, industry cards and “Talk to us” block each appear three times in the source, once per breakpoint.
Fix
Load the HubSpot form only when it scrolls into view, and trim duplicate breakpoint layers where one responsive layout will do.
LowSEO

12. Sitemap housekeeping

Evidence
/healthcare-2 is in the sitemap, but its content is project-based security and platform work (“Get critical security & platform work done without adding another full-time hire”), not healthcare. /conf26 is a post-event “Thanks for joining us at Splunk .conf26!” page that is also indexable.
Fix
Give the project page a descriptive slug with a 301 redirect, and mark event or campaign pages noindex or remove them from the sitemap.

What’s already working

  • HTTPS with HSTS, and the bare domain redirects to www with a 308
  • A canonical tag on every page checked
  • robots.txt allows crawling and points to a 464-URL sitemap
  • Blog posts have unique, descriptive titles
  • Unknown URLs return a real 404
  • No horizontal scrolling at 390 px, and almost no layout shift (CLS 0.003)

How I checked

I fetched the homepage, robots.txt, sitemap.xml and the 25 non-blog sitemap URLs, and parsed titles, descriptions, canonicals, headings, images and JSON-LD. I loaded the homepage in headless Chrome at 390 px and 1440 px to check overflow, tap targets and rendered headings, and ran a Lighthouse mobile lab test (scores vary from run to run). Everything here can be re-checked with view-source or Lighthouse.
